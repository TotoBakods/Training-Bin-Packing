# Machine Learning Approach & Process

This document outlines the machine learning pipeline used in the **Training Bin Packing** project. It explains how artificial intelligence is used to accelerate the complex process of 3D bin packing in a warehouse environment.

---

## 1. The Core Objective

Traditional algorithms for 3D bin packing (like Genetic Algorithms or Extremal Optimization) simulate thousands of combinations to find a good layout. While effective, they are extremely slow and computationally expensive.

**The Solution:** We use **Imitation Learning** (a branch of supervised learning). We train a deep neural network to look at an item's properties and the warehouse's dimensions, and instantly predict the optimal resting coordinate `(x, y, z)` and `rotation` for that item, imitating the results of the slower algorithms in a fraction of the time.

---

## 2. Model Architecture

The neural network is built using **PyTorch**. It uses a highly efficient Feed-Forward Neural Network (Multi-Layer Perceptron) defined in `ml_utils.py` as `PackingModel`.

### Network Layers
1. **Input Layer:** 10 nodes (representing the features of the item and warehouse).
2. **Hidden Layer 1:** 64 nodes (Activation: ReLU)
3. **Hidden Layer 2:** 128 nodes (Activation: ReLU)
4. **Hidden Layer 3:** 64 nodes (Activation: ReLU)
5. **Output Layer:** 4 nodes (representing the predicted `x, y, z` coordinates and `rotation`).

---

## 3. Data Processing & Features

Before data is fed into the neural network for training or inference, it must be properly formatted and normalized to help the algorithm learn efficiently.

### Inputs (Features)
For each item, 10 distinct variables are passed into the model:
- **Item Dimensions (3):** Length, Width, Height (divided by 10 for normalization).
- **Item Weight (1):** Real weight in kg (divided by 10).
- **Boolean Flags (3):** Is it fragile? Is it stackable? Can it be rotated? (represented as `1.0` or `0.0`).
- **Warehouse Dimensions (3):** Length, Width, Height of the target warehouse (divided by 100).

### Outputs (Targets)
The model tries to predict 4 values:
- `x, y, z` coordinates (normalized against the respective warehouse dimensions, e.g., `x / warehouse_length`).
- `rotation` code (normalized between 0.0 and 1.0 by dividing by 6.0).

---

## 4. The Training Process

The training logic is contained within `train_models.py`.

1. **Dataset Loading:** The script reads historical, pre-solved packing data (CSV files) from the `training_data/` directory. These CSVs contain the optimal layouts generated by older, slower algorithms.
2. **Batching:** The data is broken down into batches of `64` items at a time.
3. **Optimization Engine:** It uses the **Adam Optimizer** with a learning rate of `0.001`.
4. **Loss Function:** It uses **Mean Squared Error (MSE)**. The system calculates the distance between the AI's predicted coordinates and the "ground truth" optimal coordinates, and adjusts the network weights to minimize that error over time.
5. **Epochs:** The model trains over `50` full passes (epochs) of the dataset until the error rate flattens out.
6. **Storage:** The trained weights are compiled and saved as `.pth` files in the `models/` directory.

---

## 5. The Inference & Execution Pipeline

When a user clicks "Initiate Optimization" in the web application, the system transitions from training to real-world prediction (inference).

### Step A: Prediction (`MLOptimizer`)
The `ml_utils.py` script loads the `.pth` model into memory (`torch.no_grad()`). It feeds the current inventory features into the network and instantly outputs the normalized `(x, y, z)` and `rotation` values. Those values are then multiplied back by the warehouse dimensions to get real-world measurements.

### Step B: The Heuristic Repair
Neural networks are highly accurate but not perfect; a model might predict two boxes overlapping by a few centimeters, or floating slightly above the floor.
* To fix this, the raw predictions are sent to `repair_solution_compact()` in `optimizer.py`.
* This algorithm "snaps" items to valid constraints. It calculates strict gravitational drops (Z-axis) to ensure no item is hovering mid-air and enforces strict boundaries.

### Step C: Physics Validation
Finally, the heuristically repaired solution is sent to `physics_settle()` in `optimizer_physics.py`.
* The **PyBullet** physics engine creates a headless 3D bounding box for the warehouse.
* It drops the items into the predicted positions using their actual designated mass and a high friction coefficient.
* The simulation runs for precisely 1000 steps, resolving any micro-collisions and ensuring that heavy items don't balance unrealistically on thin items. 
* The final resting coordinates of the physics simulation are saved as the ultimate packing solution.
